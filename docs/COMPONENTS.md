## Overview
This document provides a detailed breakdown of the major components and modules within the Codex CLI project, covering both the TypeScript (`codex-cli`) and Rust (`codex-rs`) parts of the codebase.

## Codex CLI (`codex-cli`) Components
The `codex-cli` is the primary user-facing application, written in TypeScript and running on Node.js.

### Main Entry Points & Application Logic
-   **`codex-cli/bin/codex.js`**: The executable script that Node.js runs. This is the entry point defined in `package.json`.
-   **`codex-cli/src/cli.tsx`**: Handles command-line argument parsing (using `meow`) and initializes the main application UI. This is likely the first TypeScript file executed.
-   **`codex-cli/src/app.tsx`**: Contains the main React/Ink application component. It manages the overall UI layout, different views (chat, overlays), and orchestrates interactions between UI and agent logic.
-   **`codex-cli/src/cli-singlepass.tsx`**: Appears to be an entry point or logic for a non-interactive or single-pass execution mode (e.g., when a prompt is provided directly as a CLI argument for a quick task).
-   **`codex-cli/src/approvals.ts`**: Manages the user approval flow for suggested actions (file edits, command execution), respecting the `approvalMode` setting.
-   **`codex-cli/src/parse-apply-patch.ts`**: Logic for parsing and applying diff patches to files.

### UI Components (`codex-cli/src/components/`)
This directory contains various React components (using Ink) for building the terminal UI.
-   **`chat/`**: Components related to the chat interface, including message history display (`message-history.tsx`), input editor (`multiline-editor.tsx`), command review (`terminal-chat-command-review.tsx`), and the main chat view (`terminal-chat.tsx`).
-   **Overlays**:
    -   `approval-mode-overlay.tsx`: UI for selecting or confirming the approval mode.
    -   `diff-overlay.tsx`: Displays file diffs to the user.
    -   `help-overlay.tsx`: Shows help information.
    -   `history-overlay.tsx`: Displays command or session history.
    -   `model-overlay.tsx`: UI for selecting AI models.
    -   `sessions-overlay.tsx`: UI for managing sessions.
    -   `typeahead-overlay.tsx`: Potentially for command or file path suggestions.
-   **`onboarding/`**: Components for the first-time user experience.
-   **`select-input/`**: Reusable select input component.
-   **`vendor/`**: Third-party UI components or customized versions.

### Agent Logic (`codex-cli/src/utils/agent/`)
This directory is central to Codex's ability to act as an AI agent.
-   **`agent-loop.ts`**: Core loop for processing user input, interacting with the AI model, and handling responses.
-   **`apply-patch.ts`**: Handles applying file patches generated by the AI.
-   **`exec.ts`**: Responsible for executing shell commands suggested by the AI, including sandboxing.
-   **`handle-exec-command.ts`**: Specific logic for managing command execution flow.
-   **`platform-commands.ts`**: Platform-specific command utilities.
-   **`review.ts`**: Potentially for code review features or self-correction loops.
-   **`sandbox/`**: Contains implementations for sandboxing command execution on different platforms (e.g., `sandbox/macos.ts`, `sandbox/docker.ts`).

### Utilities (`codex-cli/src/utils/`)
A collection of helper modules for various functionalities.
-   **`config.ts`**: Loads and manages user configuration (from `~/.codex/config.json` or `.env`).
-   **`openai-client.ts`**: Manages communication with the OpenAI API and other compatible AI providers.
-   **`model-utils.ts`, `model-info.ts`**: Utilities related to AI model information and selection.
-   **`get-diff.ts`**: Generates diffs between file states.
-   **`file-system-suggestions.ts`**: Provides suggestions for file paths.
-   **`logger/`**: Logging utilities.
-   **`storage/`**: Handles persisting data like command history (`command-history.ts`) and session rollouts (`save-rollout.ts`).
-   **`terminal.ts`**: Utilities for interacting with the terminal.
-   **`version.ts`**: Manages version information for the CLI.

### Hooks (`codex-cli/src/hooks/`)
Custom React hooks for managing state and side effects in UI components.
-   **`use-confirmation.ts`**: Hook for handling user confirmation dialogs.
-   **`use-terminal-size.ts`**: Hook to get and respond to terminal size changes.

## Codex RS (`codex-rs`) Components
The `codex-rs` project is a Cargo workspace containing several Rust crates.

### Core Logic (`codex-rs/core/`)
-   **`src/lib.rs`**: Main library file for `codex-core`.
-   **`src/codex.rs`, `src/codex_wrapper.rs`**: Central structs and logic for the Codex agent in Rust.
-   **`src/client.rs`, `src/client_common.rs`**: Handles communication with AI model providers.
-   **`src/config.rs`, `src/config_profile.rs`**: Manages configuration (from `~/.codex/config.toml`).
-   **`src/exec.rs`, `src/exec_linux.rs`**: Logic for executing commands, including Linux-specific sandboxing.
-   **`src/safety.rs`, `src/landlock.rs`, `src/seatbelt_base_policy.sbpl`**: Components related to sandboxing and secure command execution.
-   **`src/mcp_connection_manager.rs`, `src/mcp_tool_call.rs`**: Part of the Multi-Codex Protocol implementation for tool usage.
-   **`src/project_doc.rs`**: Handles loading and processing `AGENTS.md` files.
-   **`src/protocol.rs`**: Defines internal communication protocols or data structures.

### Main CLI Executable (`codex-rs/cli/`)
-   **`src/main.rs`**: Entry point for the `codex` Rust executable.
-   **`src/lib.rs`**: Library code for the CLI.
-   **Responsibilities**: Parses command-line arguments (using `clap`), initializes configurations, and dispatches to different subcommands or modes of operation (e.g., TUI, exec, MCP server). It also includes specific sandboxing logic for Linux (`src/linux-sandbox/`) and macOS (`src/seatbelt.rs`).

### Terminal UI (TUI) (`codex-rs/tui/`)
-   **`src/main.rs`**: Entry point if the TUI is run as a standalone executable.
-   **`src/lib.rs`**: Core library for the TUI.
-   **`src/app.rs`**: Main application structure for the TUI, managing state and events.
-   **`src/tui.rs`**: Handles terminal rendering using `ratatui`.
-   **`src/chatwidget.rs`, `src/conversation_history_widget.rs`**: UI components for the chat interface.
-   **`src/user_approval_widget.rs`**: Component for handling user approvals.
-   **`src/markdown.rs`**: Markdown rendering for the TUI.

### Headless Execution (`codex-rs/exec/`)
-   **`src/main.rs`**: Entry point for the `codex-exec` headless utility.
-   **`src/lib.rs`**: Library code.
-   **Responsibilities**: Provides a non-interactive way to run Codex tasks, suitable for scripting or CI/CD pipelines. It focuses on direct command execution and processing based on input parameters.

### Execution Policy (`codex-rs/execpolicy/`)
-   **`src/main.rs`**: Potentially a standalone tool for managing or validating execution policies.
-   **`src/lib.rs`**: Library code.
-   **`src/policy.rs`, `src/policy_parser.rs`**: Defines and parses policies that likely govern what commands Codex is allowed to run, or under what conditions.
-   **`src/default.policy`**: A default set of execution policies.

### Multi-Codex Protocol (MCP) Crates
-   **`codex-rs/mcp-types/`**: Defines the data structures and schema for MCP.
    -   `schema/`: Contains JSON schema definitions for the protocol.
    -   `generate_mcp_types.py`: Script to generate Rust types from the schema.
-   **`codex-rs/mcp-client/`**: Implements the client-side logic for MCP, allowing Codex to consume tools.
-   **`codex-rs/mcp-server/`**: Implements the server-side logic for MCP, allowing external tools to register with Codex.
    -   `src/codex_tool_runner.rs`: Runs tools that conform to the Codex tool specification.

### Shared Libraries
-   **`codex-rs/common/`**: Utility code shared among other `codex-rs` crates (e.g., CLI argument parsing helpers, timing utilities).
-   **`codex-rs/ansi-escape/`**: Library for handling ANSI escape codes.
-   **`codex-rs/apply-patch/`**: Library for parsing and applying diff patches (similar to its TypeScript counterpart).

## Inter-Component Relationships
-   **`codex-cli` and `codex-rs`**: As of the current understanding, `codex-cli` is the primary, stable tool. `codex-rs` is being developed with potential for `codex-cli` to delegate tasks (like sandboxed execution) to Rust binaries (e.g., via `CODEX_RUST=1` environment variable). Eventually, `codex-rs` might supersede `codex-cli` or they might integrate more deeply.
-   **Within `codex-rs`**:
    -   `codex-rs/cli` acts as a multitool, capable of launching the `tui` or `exec` modes.
    -   `codex-rs/core` provides the fundamental business logic used by `cli`, `tui`, and `exec`.
    -   MCP crates (`mcp-client`, `mcp-server`, `mcp-types`) are used by `codex-rs/core` to interact with external tools.
    -   `common`, `ansi-escape`, `apply-patch` provide utility functions to other Rust crates.
