## Concept Overview
Codex assists users in generating scripts for common preprocessing tasks on health datasets (e.g., cleaning, transformation, normalization). For anonymization or pseudonymization, Codex acts as a **scripting assistant to call user-specified, validated external tools or libraries**, rather than implementing such logic itself. The emphasis is on augmenting the user's ability to script these tasks, not on Codex making autonomous decisions about sensitive data handling.

## Target Domain(s)
-   Health Research
-   Bioinformatics
-   Clinical Data Analysis
-   Epidemiology

## CRITICAL WARNING: Ethical and Security Considerations
Handling health data requires extreme caution and strict adherence to legal and ethical frameworks like HIPAA, GDPR, CCPA, etc.
-   **Codex Is Not a Compliance Tool**: Codex, as an AI assistant, cannot ensure compliance. The user is SOLELY responsible for ensuring all data handling practices meet legal, ethical, and institutional requirements.
-   **No Autonomous Sensitive Data Operations**: Codex should NEVER be designed or prompted to autonomously perform operations that could compromise patient privacy or data security (e.g., deciding what constitutes PII/PHI, implementing de-identification algorithms itself).
-   **User Responsibility**: The user must provide, validate, and take full responsibility for any external anonymization/pseudonymization tools, libraries, or algorithms that Codex is asked to script calls to.
-   **Sandboxing and Data Exposure**: Even generated scripts run locally. Users must ensure the environment where Codex and its generated scripts operate is secure and appropriate for handling sensitive data. Logs or intermediate files generated by scripts should not inadvertently expose sensitive information.
-   **`AGENTS.md` for Safeguards**: This file should be used to define strict rules, allowed libraries, and prohibited operations when dealing with potentially sensitive data.

**This feature should only be approached if robust safeguards and clear user responsibility frameworks can be established.**

## Detailed Description

### Core Functionality - Preprocessing
1.  **Interpret Preprocessing Task**: Codex parses user prompts for tasks like:
    -   Loading health data (e.g., CSV, Excel, Parquet).
    -   Data type conversion (e.g., ensuring dates are datetime objects).
    -   Handling missing values (e.g., imputation by mean/median/mode, flagging missing entries).
    -   Filtering records based on criteria.
    -   Normalization or scaling of numerical features.
    -   Reshaping data (e.g., pivoting, melting).
    -   Feature engineering (e.g., creating age groups from age).
2.  **Script Generation**:
    -   Generates Python scripts (e.g., using Pandas, NumPy, Scikit-learn) to perform these tasks.
    -   Scripts are designed to be transparent and auditable.

### Core Functionality - Guided Anonymization/Pseudonymization Scripting
This is the most sensitive part and must be user-driven.
1.  **User Specifies Tool/Library**: The user explicitly tells Codex which pre-validated anonymization tool or library to use and what columns to apply it to.
    *Prompt Example*: `"codex, using my 'custom_anon_lib.py' script's 'pseudonymize_id' function, apply it to the 'patient_mrn' column in 'records.csv'. Load the script from './utils/'"`
2.  **Script Generation for Tool Invocation**:
    -   Codex generates a Python script that:
        -   Loads the data.
        -   Imports or calls the user-specified external script/library/function.
        -   Applies the user's function to the specified columns.
        -   Saves the modified dataset.
    -   **Codex does NOT generate the anonymization logic itself.** It only scripts the *use* of the user's provided logic.
3.  **Emphasis on User Validation**: Codex should remind the user to validate the anonymization script and its outputs thoroughly.

### Example Interactions

**Example 1 (Preprocessing - Missing Data and Normalization):**
*User Prompt*: `"codex, for 'lab_results.csv', impute missing 'cholesterol' values with the column median, then normalize 'bilirubin' and 'alt' columns using MinMaxScaler."`

*Codex Actions*:
1.  Generates `preprocess_labs.py`:
    ```python
    import pandas as pd
    from sklearn.preprocessing import MinMaxScaler

    df = pd.read_csv('lab_results.csv')

    # Impute missing cholesterol
    median_cholesterol = df['cholesterol'].median()
    df['cholesterol'].fillna(median_cholesterol, inplace=True)
    print(f"Missing 'cholesterol' imputed with median: {median_cholesterol}")

    # Normalize bilirubin and alt
    scaler = MinMaxScaler()
    df[['bilirubin', 'alt']] = scaler.fit_transform(df[['bilirubin', 'alt']])
    print("'bilirubin' and 'alt' columns normalized.")
    df.to_csv('lab_results_processed.csv', index=False)
    print("Processed data saved to 'lab_results_processed.csv'")
    ```

**Example 2 (Guided Pseudonymization Scripting):**
*User Prompt*: `"codex, I have a script 'my_id_scrambler.py' with a function 'scramble(identifier)'. Generate a python script to load 'admissions.csv', apply 'my_id_scrambler.scramble' to the 'PATIENT_ID' column, and save as 'admissions_pseudo.csv'. The script is in the current directory."`

*Codex Actions*:
1.  **Warning**: Codex might first issue a reminder about handling sensitive data and user responsibility.
2.  Generates `apply_pseudonymization.py`:
    ```python
    import pandas as pd
    import my_id_scrambler # User's script

    print("INFO: This script applies a user-provided pseudonymization function.")
    print("INFO: The user is responsible for validating the function and its output for compliance.")

    df = pd.read_csv('admissions.csv')

    if 'PATIENT_ID' in df.columns:
        df['PATIENT_ID_pseudo'] = df['PATIENT_ID'].apply(my_id_scrambler.scramble)
        # Optionally, drop original ID: df.drop(columns=['PATIENT_ID'], inplace=True)
        # User should be prompted about dropping original vs. keeping both for review
        print("Applied 'my_id_scrambler.scramble' to 'PATIENT_ID' column.")
    else:
        print("Error: 'PATIENT_ID' column not found.")

    df.to_csv('admissions_pseudo.csv', index=False)
    print("Pseudonymized data saved to admissions_pseudo.csv")
    print("IMPORTANT: Please thoroughly review 'admissions_pseudo.csv' for correctness and compliance.")
    ```

### Leveraging `AGENTS.md` for Safeguards
-   Define **allowed lists** of external scripts or libraries for sensitive operations.
-   Specify **prohibited columns** or data patterns that Codex should refuse to script direct manipulations for, forcing user to use external validated tools.
-   Embed **reminders and warnings** about data privacy and compliance that Codex can output when such tasks are initiated.
-   Store paths to approved data handling utility scripts.

## How Codex CLI/Agent Features Are Leveraged
-   **Natural Language Processing**: To understand preprocessing steps and, crucially, to identify user-specified external tools for sensitive operations.
-   **Code Generation**: To create Python scripts for data loading, transformation, and *calling* user-provided functions.
-   **File System Interaction**: Reading data, writing scripts, saving processed/pseudonymized data.
-   **Command Execution**: Running the generated scripts (always with explicit user approval for scripts handling sensitive data).
-   **Strict Guidance from `AGENTS.md`**: To enforce any safety protocols, allowed tools, or reminders.

## Potential Benefits
-   **Efficiency in Routine Preprocessing**: Speeds up common, non-sensitive data cleaning and preparation tasks.
-   **Reduced Scripting Errors**: Helps avoid bugs in boilerplate preprocessing code.
-   **Guided Workflow for Sensitive Tasks**: Provides a framework for users to apply their own validated anonymization tools in a scripted, reproducible way.
-   **Auditability**: Generated scripts provide a record of preprocessing steps and which external functions were called for sensitive transformations.

## Considerations & Challenges
-   **Primary Challenge: Safety and Compliance**: This cannot be overstated. The system must be designed to prevent Codex from making autonomous decisions about sensitive data or implementing de-identification itself. User control and responsibility are paramount.
-   **Validation of External Tools**: Codex cannot validate the user's external anonymization scripts. The entire security and compliance burden rests with the user providing these tools.
-   **Complexity of De-identification**: True, robust de-identification is extremely complex and context-dependent. This feature only aims to script the *application* of user-chosen methods.
-   **Data Leakage**: Risk of exposing sensitive data through logs, intermediate files, or even prompts if users are not careful. Prompts themselves should not contain actual PHI/PII.
-   **User Understanding**: Users must clearly understand the limitations and responsibilities when using this feature for tasks involving sensitive data.
-   **Scope Creep**: Danger of users trying to push Codex to perform more autonomous sensitive data tasks than it's designed for. Strict input validation and warnings are needed.
-   **Maintaining Context**: For multi-step preprocessing pipelines, Codex needs to maintain context or allow users to chain operations on datasets.
