# Prompt‑Analyzer Code Walk‑through

This document provides a comprehensive explanation of the _entire_ code that
lives in `codex-cli/examples/prompt-analyzer/`. The goal is to help future
contributors (or simply curious readers) understand **what the example does,**
**how it does it** and **where to start** when they want to extend or reuse the
components.

---

## 1. Big‑picture overview

```
prompt-analyzer/
├── run.sh            # Shell helper that instantiates a new "run" directory
├── runs/             # Run‑time artefacts created by run.sh – ignored by git
├── task.yaml         # Codex task description (used by run.sh)
└── template/         # Re‑usable boiler‑plate that is copied into each run
    ├── cluster_prompts.py  # 🧠  The heart of the utility (Python)
    ├── prompts.csv         # Sample input data (213 ChatGPT system prompts)
    ├── README.md           # End‑user instructions
    ├── Clustering.ipynb    # Notebook that explores the same pipeline
    ├── analysis*.md        # Example reports generated by the script
    └── plots*/             # Example PNG plots referenced by the reports
```

At its core the example demonstrates an **end‑to‑end NLP pipeline** that

1. embeds a list of text prompts with the OpenAI Embedding API,
2. discovers natural groupings with unsupervised clustering (K‑Means or
   DBSCAN),
3. lets ChatGPT _name_ and _describe_ every cluster,
4. generates a human‑readable Markdown report, and finally
5. saves a couple of diagnostic plots (cluster sizes & t‑SNE projection).

The surrounding `run.sh` / `task.yaml` scaffolding is merely convenience glue
so that the example plugs nicely into **Codex CLI’s** workflow.

---

## 2. The scaffolding layer (`run.sh` & `task.yaml`)

### 2.1 `task.yaml`

This YAML file does _not_ directly influence the Python pipeline. Instead it
is consumed by Codex CLI to describe what we want the assistant to build:

- **`name`** – an identifier (`prompt-analyzer`).
- **`description`** – a multi‑line prompt that is sent to the model when a
  _run_ starts. In this example the description asks the assistant to evolve
  the existing clustering work into an interactive Streamlit app. The current
  implementation therefore acts as a _starting point_ for this broader goal.

### 2.2 `run.sh`

`run.sh` is a convenience wrapper that

1. creates an incrementally numbered directory (`runs/run_1`, `runs/run_2`, …)
   so that each attempt remains self‑contained,
2. copies the content of `template/` into the fresh directory (unless no
   template exists), and
3. finally launches Codex CLI with the prompt pulled from `task.yaml`.

Key implementation details:

- Written in portable `bash`.
- Uses `yq` and `jq` to parse YAML/JSON in a cross‑platform manner.
- Supports `--auto-confirm` to skip the _Y/N_ guard when executed from CI.

While _run.sh_ is helpful operationally, it does not influence the clustering
logic and can be safely ignored if you only care about the Python code.

## 3. Python pipeline (`template/cluster_prompts.py`)

The script is intentionally **self‑contained** – there are **no external
imports from the repository**, only standard Python + PyPI packages. A handful
of imports are **lazy‑loaded** so that running `python cluster_prompts.py
--help` returns instantly.

Below we walk through the file top‑to‑bottom, reflecting the natural order of
execution.

### 3.1 CLI parsing (`parse_cli()` – lines 20‑70)

`argparse` is used with `ArgumentDefaultsHelpFormatter` so that the `--help`
output automatically lists default values. The most relevant flags are:

- `--csv` – path to the input CSV (must contain a `prompt` column).
- `--cache` – optional JSON cache to avoid re‑embedding unchanged texts.
- `--cluster-method` – `kmeans` _(default)_ or `dbscan`.
- `--k-max` / `--dbscan-min-samples` – algorithm‑specific knobs.
- `--embedding-model`, `--chat-model` – OpenAI model IDs.
- `--output-md`, `--plots-dir` – where artefacts are written.

The parsed `Namespace` is forwarded unchanged to `main()` so all subsequent
steps have access to _exactly_ the same configuration.

### 3.2 Embedding helpers

Two functions implement the embedding phase:

1. `_lazy_import_openai()` – defers the heavy import _until actually needed_.
2. `embed_texts()` – sends batched requests (`batch_size=100`) to the Embedding
   API. Responses are appended in input order to preserve deterministic
   alignment between prompts and vectors.

`load_or_create_embeddings()` (
lines 95‑150) orchestrates **caching**:

- If a `--cache` file is given and exists, it is parsed as JSON into a
   `dict[str, list[float]]` (mapping _prompt → vector_).
- Missing embeddings are fetched from the API and **immediately written back**
  so later executions are incremental.
- Finally, a `pandas.DataFrame` is returned where each column is a dimension of
  the embedding space and the index matches the original CSV rows.

### 3.3 Clustering helpers

All scikit‑learn imports are again postponed (`_lazy_import_sklearn_cluster`).

#### 3.3.1 `cluster_kmeans()`

- Loops over `k = 2 … k_max`.
- Fits K‑Means **once per k** (`n_init="auto"` for scikit‑learn ≥ 1.4).
- Evaluates the **silhouette score**; keeps the best.
- Prints the selected _k_ and returns the label vector.

This simple heuristic is surprisingly robust for short‑ish text datasets while
keeping the implementation tiny (no genetic algorithms, no elbow plot etc.).

#### 3.3.2 `cluster_dbscan()`

- Scales features with `StandardScaler` (DBSCAN is distance‑based).
- Estimates a reasonable `eps` via the **k‑distance** rule (90‑th percentile of
  the distances to the _min_samples_‑th neighbour).
- Returns the label vector where _noise_ is marked as `-1`.

### 3.4 LLM‑assisted cluster labelling (`label_clusters()`)

For each **unique label** (except `-1`):

1. Sample up to 12 representative prompts.
2. Craft a prompt that asks ChatGPT for a **short title** (≤ 4 words) and a
   concise description.
3. Parse the reply as JSON – robust against Markdown code fences by slicing
   the substring between the first `{` and last `}`.

If the call fails (network, quota, JSON decode…) the cluster is given a dull
`Cluster N` placeholder and the script continues – i.e. **fault‑tolerant by
design**.

### 3.5 Report generation (`generate_markdown_report()`)

Writes a **single stand‑alone** Markdown file that contains:

- A high‑level _Overview_ with total prompts, chosen method, silhouette score
  (when applicable) and a summary table.
- One section per cluster with five example prompts.
- Dedicated sections for _noise_ (`-1`) **and** _ambiguous prompts_ (K‑Means
  only – see below).
- A short note that references the PNG plots.

The function receives a dict `outputs` so additional metadata can be surfaced
without touching the signature again (extensibility).

### 3.6 Plotting helpers (`create_plots()`)

Generates two figures via `matplotlib`:

1. `cluster_sizes.png` – bar chart sorted by descending member count.
2. `tsne.png` – 2‑D t‑SNE projection coloured by cluster label.

If the CSV contains a boolean column `for_devs` the respective prompts are
outlined with a black circle on the t‑SNE to aid manual inspection.

### 3.7 Ambiguity detection (K‑Means only)

After the _final_ K‑Means model is fitted the script computes for every sample
the ratio of the distance to the **closest centroid** versus the **2nd‑closest
centroid**. A ratio > 0.9 indicates that the point sits almost equidistant
between two clusters and is therefore flagged as _potentially ambiguous_.

### 3.8 `main()` glue code

Putting the pieces together in 5 linear stages:

1. **Load CSV** → ensure `prompt` column exists.
2. **Embeddings** (with caching).
3. **Clustering** → stores summary stats in `outputs`.
4. **LLM labelling** → dictionary `meta` mapping _label → {name, description}_.
5. **Plots & Markdown** → artefacts are written to disk.

Errors are propagated by default (no `try/except` in `main`) because the
individual helper functions already catch and downgrade _recoverable_ issues.

## 4. Auxiliary files inside `template/`

- **`prompts.csv`** – A sample dataset that contains 213 _“System”_ prompts
  scraped from various ChatGPT conversations. Useful for a quick test‑run.
- **`analysis.md` / `analysis_dbscan.md`** – Example outputs so that readers
  can see what to expect without running the pipeline.
- **`Clustering.ipynb`** – A Jupyter notebook that mirrors the Python script
  but with rich, step‑by‑step visualisations. Handy when you want to tweak
  hyper‑parameters interactively.
- **`plots/` & `plots_dbscan/`** – Pre‑computed PNGs referenced by the
  `analysis*.md` reports above.

---

## 5. Extending or re‑using the code

- **Different distance metrics** – swap out K‑Means/DBSCAN for HDBSCAN or
  Hierarchical Clustering; only `cluster_*` helper functions need to be added.
- **Alternative LLM provider** – replace the OpenAI client in
  `_lazy_import_openai()` with any other SDK that supports chat completions and
  embeddings.
- **Interactive front‑end** – The current script is _batch‑oriented_. Turning
  it into a Streamlit app (as hinted by `task.yaml`) mainly requires:
     1. File upload widget → call `cluster_prompts` with in‑memory dataframe.
     2. Display of `analysis.md` inside an `st.markdown()` frame.
     3. Embedding of the generated PNGs via `st.image()`.
- **Unit tests** – Because the heavy lifting depends on external APIs it is
  recommended to _mock_ those in tests; the modular structure of the helpers
  makes that straight‑forward.

---

## 6. Recap

`examples/prompt-analyzer` showcases a **complete yet minimalistic** analytics
pipeline for text prompts. The heart lies in a single ~600 line Python file
that keeps _every_ stage (embedding → clustering → LLM labelling → reporting)
in one place while keeping each concern neatly separated.

When you understand `cluster_prompts.py` you understand 95 % of the example –
everything else is operational sugar around it.

Happy hacking 🚀
